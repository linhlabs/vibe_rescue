# v0.8-preview — capability contract

[Tiếng Việt](V0.8_PREVIEW.vi.md) · Package metadata: `0.8.0-preview`
(packaging tools may normalize it to `0.8.0rc0`). This is a **preview of the
generic workflow**, not a certification for every repository. Install from the
source checkout as shown in the README; a Python wheel is not supported yet.

## What another team can run today

```bash
python scripts/repo_explorer.py --generic \
  --root /path/to/project --sources src tests \
  --profile agent --profile pii \
  --out /path/to/project/VIBE_RESCUE/source-explorer.html
```

Choose only approved source directories. The command runs offline and writes
EN/VI `handoff.html` + `HANDOFF.md` packets, `REVIEW_WORKSHEET.md` in both
languages, `architecture.html/.json`, and
`source-explorer.html/.json` together. Start with the handoff; its source links
lead into the Atlas and function explorer. The architecture page connects
bounded documentation claims to directory blocks, Python
source-level calls/imports, exact backtick step anchors, config/prompt *paths*,
control candidates and explicit unknowns. The second page lets engineers inspect
Python parameters, callers/callees, guards and raises. Other supported languages
enter the file inventory; this generic command does not connect their functions
to Python or to UI/HTTP routes. The separate `logic_atlas.py` has language-specific
maps with the limits described in [LOGIC_ATLAS.md](LOGIC_ATLAS.md).

`rescue_voyage.py --path /path/to/project --stages map,prove,review` can run the
scanner and agent-review workflow on a chosen target when its source and provider
policy permit it. Unlike the scoped Atlas, MAP inspects the target root. Plan,
repair and merge need owner decisions; worktrees and diff checks do not sandbox
agent/scanner processes. See [SECURITY.md](../SECURITY.md) and the
[owner pact](OWNER_PACT.md) before using FIX on a real project.

## What the output proves

<!-- markdownlint-disable MD013 -->

| Output | Evidence level | Reviewer still needs to do |
| --- | --- | --- |
| Handoff block, journey and control card | Static source/documentation evidence | Assign a reviewer and collect target-specific proof; the packet is not a safety verdict. |
| Function, call/import, file and line | Static source observation | Check dynamic dispatch and trace the served path. |
| Purpose or journey step from docs | Documented claim | Check that the document matches the current code. |
| Exact function ID in backticks | Exact source binding | Verify the step actually executes for the target scenario. |
| Harness, PII/PHI, medical, billing or swarm card | Candidate or not located in scope | Trace intake, authority, egress, final output and failures; collect redacted receipts. |
| Scanner or model review | Finding or hypothesis | Reproduce, assess impact, review proposed fix and run target tests. |

<!-- markdownlint-enable MD013 -->

A detailed control review is written by an independent human reviewer after
following code paths and focused tests. Vibe
Rescue now generates the **starting handoff for any approved scope**, with
specific source links and probes. It does not automatically reproduce that
reviewer's runtime or clinical conclusions. A green unit test or a function
named `mask` cannot establish safety or production readiness.

## Preview evidence and remaining gates

- On the public synthetic [support-ticket example](../examples/support_ticket/),
  the same generic command mapped 6 code files, 6 blocks, 8 static relations
  and 5/5 explicitly named journey functions; its EN/VI handoffs and preserved
  review worksheets are checked in. A fixture keeps unknown function IDs
  unknown. This tests portability of EXPLORE, not a live full-stack request or
  FIX.
- The [Architecture Atlas contract](ARCHITECTURE_ATLAS.md) documents evidence
  states, scope exclusions and current parser limits. The long-term
  [product objective](PRODUCT_NORTH_STAR.md) and [V1.0 plan](../PLAN.md) remain
  active; `v0.8-preview` does not close their control or release gates.
- A wheel build currently fails at setuptools' ambiguous flat-layout package
  discovery. The source-checkout commands above work; do not advertise
  `pip install vibe-rescue` until distribution layout and installed entry
  points are designed and tested.
- Before claiming a target is production-ready, its team must independently
  validate the exact build and active configuration with UAT/production traces,
  failure injection, security review and domain-specific test cases. Sensitive
  artifacts stay in that team's controlled workspace.
